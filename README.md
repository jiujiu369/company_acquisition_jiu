# 商品资料批量采集与原图下载

项目仅提供商品采集和资料准备工作流，不执行上架或修改店铺商品。输入淘宝/天猫商品或店铺链接，选择电脑上的实际保存目录，自动生成独立商品资料包。保留暂停、继续、失败重试、原图缓存和浏览器会话。图片按 CDN 原始响应字节保存，不缩放、裁切、压缩或覆盖原图。推荐内容和店铺装饰不进入资料；有明确商品用途证据的可取得附加素材会单独保存。

## 当前采集字段（2026-10-09）

新建采集可选择“仅 Excel 表格（含一张商品主图）”或“Excel 表格＋全部原图”，默认仅 Excel。该选择随任务、店铺子商品、暂停继续、失败重试和新目录复用保存。仅 Excel 模式只下载一张明确的商品主图用于表格观察，跳过详情图片加载及其它图片下载；没有取得主图时主图列留空，表格仍可保存。历史原图不删除，仅 Excel 模式不另复制到本次资料包。旧 API 请求未指定 `collect_images` 时保留带全部图片的行为。

每件自动保存和下载的表格命名为 `商品名称.xlsx`，采用最终商品名称（含人工修订）。非法文件字符替换为下划线，过长名称按保存路径容量截短；批量 ZIP 内同名文件加 `_2`、`_3` 等序号，避免覆盖。历史 `商品资料.xlsx` 资料包仍可读取和校验。在任务、店铺和已保存商品处可直接“导出 Excel”，进度页支持“逐商品导出本页 Excel”。每件商品一个独立 Excel，多件商品或店铺下载为 ZIP，其中逐件保存 XLSX，绝不合并成一张商品总表。每个 SKU 一行，无 SKU 时仍保留商品一行；商品名称后为商品主图列，主图只嵌入一次，来源链接也只填写一次。其余列为安装方式、导线材质、型号、销售规格、SKU编号、价格、数量、包装单位、导线截面积、适用线缆类型、一口价、总库存和固定设置。SKU编号使用 `JG16-12` 等实际型号文字，销售规格保留完整标签，来源数字ID只在内部证据中保留，不作为表格中的SKU编号。价格是整包价格，数量是包装数量；截面积和线缆类型优先取该 SKU 明确规格，回退到已取得的商品属性。没有取得的变量保持真正的空白，真实零值保留。

固定设置：上架时间“放入仓库”、发货时间“48小时”、发货地“大陆及港澳台  单一发货地  浙江温州”、提取方式“使用物流配送”、运费“包邮”。这些是用户指定的填写配置，不从来源店铺推测。Excel 的总库存只取明确取得或人工填写的商品总库存，不从包装数量或 SKU 默认库存9999推算；未取得时留空。Excel 使用数字价格/数量及文本型号SKU编号，支持筛选并冻结表头。国标JG商品的型号按商品系列填写“国标JG”，不附加JG16-12等SKU型号及包装数量；完整SKU规格和原始型号证据保留，明确人工修订优先。

主要结果、JSON、CSV 和离线结果页集中展示商品名称、型号，以及每个 SKU 的名称、包装数量、包装单位、每包价格和填写库存。例如 `JG10-6（20只）`、页面价格 `21.7` 对应包装数量 `20`、单位 `只`、每包价格 `21.70`、默认库存 `9999`。价格保留整包价格，不除以包装数量。

包装数量只取 SKU 名称或规格中明确的包装数量，不从型号数字、库存、起订量或极数推测；多个包装数量互相冲突、包含范围或分数时留空。未知数量、单位、价格留空，价格区间也不伪造为单一价格。每个 SKU 的填写库存默认 `9999`，来源标为 `default_configuration`（CSV 显示“默认填写”），不是来源商品实际库存。导入的来源库存仅保留为证据，不覆盖填写库存；人工修正包装数量、价格或库存后采用修正值，再次采集保留人工修订。

完整度只检查商品名称、型号和 SKU 包装信息，不再因类目、条码、上架设置等后台字段缺失而要求补齐。缺少的核心字段可在“人工补充或修正资料”中填写。原图下载、图片关联和历史原始证据保留；已有商品资料在读取时投影成新字段，无需删除或覆盖历史快照。只有图片文字而没有可读取 SKU 名称的页面仍须人工补充，当前没有启用 OCR。

## 商品资料保存与恢复

1. 点击“商品采集”的“选择文件夹”，弹出 Windows 资源管理器样式的选择窗口，可浏览磁盘、选择已有文件夹或点击“新建文件夹”。页面只显示选好的完整路径，不需要输入地址；取消保留原选择，记住上次选择。开始前检查存在及可写，选中不可写目录仍显示所选位置并提示重新选择。每批建立 `批次_时间_标识/商品ID_短标题/版本_时间_标识/`。中文、空格和非法标题字符有处理，过长路径明确报错，可换较短目录补存。
2. 选择“复用已有资料”或“重新读取最新资料”。不同批次任务独立，店铺子商品继承目标；暂停、重试及重启继续使用原任务目录。复用展示原资料时间；刷新保留快照和人工值。
3. 进度页分别显示采集状态、采集范围内必填完整度、资料包保存状态。保存失败不撤销采集结果，可原目录或改目录补存。未完整包没有完成标记，不会显示保存成功。
4. “查看结果”先显示商品名称、型号、缺失/待确认和 SKU 包装信息及图片关系。展开“人工补充或修正资料”选择字段、值、状态、单位及依据；修改只保存本地修订，新资料包采用最终值并保留旧版本。来源 SKU 删除后保留旧人工修订并提示，不贴到其他规格。

每件资料包包括 `商品名称.xlsx`、`product.json`、`product.csv`、`skus.csv`、`README.html`、`detail.html`、`media_manifest.json`、`sources.json`、`provenance.json`、`issues.json`、实际取得的 `assets/` 以及成功校验后生成的 `package.complete.json`。打开 `README.html` 人工检查，详情按文字/图片顺序引用本地素材；整个版本目录移动后仍可离线查看。相同文件的不同用途和重复详情位置分别保留，文件只复制一份，ZIP 不再重复写入旧 `images/` 目录。新包的完成清单声明 Excel 能力、记录表格文件名并校验表格，升级前没有 Excel 的历史资料包仍可校验。

导出 JSON 使用 `schema_version=2.0`、`collection_profile=sku_package`：`fields` 保存商品名称及明确取得的商品价格、总库存，`attributes` 保存型号及用户要求的安装方式、导线材质、截面积、适用线缆类型等已取得属性，`skus` 每个规格一项，核心字段为 `name`、`package_quantity`、`package_unit`、`package_price`、`stock` 和 `stock_source`。`specifications` 保留原规格组合。未知字段省略并在 `collection_summary` 集中列出；明确未设置、不适用、获取失败的状态和依据保存在 `field_states`。`provenance.json` 保存原始字段证据、默认配置依据和人工修订，`issues.json` 保存缺失与待确认事项。内部准备快照仍保留原 `collected`、`effective` 编辑结构和额外来源字段，不影响历史记录。

`product.csv` 每件商品一行，保存名称和型号；`skus.csv` 每个 SKU 一行，以中文列名列出 SKU 名称、包装数量、包装单位、每包价格、库存、库存来源和图片关联。CSV 使用 UTF-8 BOM 并保护公式输入，供后续填写，**没有宣称可以直接导入淘宝**。`source_product_id`、`source_sku_id` 仅用于追溯，不能作为未来新商品/SKU ID。未明确的包装数量或单位留空。

“完整资料 ZIP”及自动保存包的 `export_mode=package`，本地路径根据实际复制并校验成功的素材生成。仅下载“资料 JSON（不含素材）”时 `export_mode=metadata_only`，只提供素材来源链接，不输出无法在下载目录打开的本地路径。需要离线图片、视频和详情，请下载完整 ZIP 并保留整个目录。缺失素材的包保持未完整状态，不产生完成标记；校验除文件哈希外还检查 JSON 所引用的素材是否包含在包内。

字段状态为已取得、明确未设置、不适用、未获取、获取失败；识别待确认另行标记。公开价格/库存提示在内部 `buyer_display` 中保留作为来源证据。每包价格采用该 SKU 的公开页面价格，填写库存默认9999，不累加为商品总库存。安装方式、导线材质等用户要求的变量取得时展示和导出，未知时留空，不进入核心必填检查。

物流设置不从来源页面主动采集，也不进入必填检查；Excel 按上述用户指定的固定数据填写上架、发货和配送设置。3:4 主图及店铺中分类未纳入本次，旧原始证据不清理。历史上架设置和销售状态是来源记录。“采集范围内必填齐全”不表示满足所有上架条件。

当前卖家后台浏览器连接不可读取，原商品的实际库存、编码、上架设置、区域限售和可编辑售后等，不能声称已取得。官方导出入口/格式未核实。结果页可读取本地已保存商品补充 JSON，按商品/SKU ID 校验，拒绝新建表单记录，全部导入值标记待确认；刷新公开资料会保留这些补充来源及原读取时间。图片 OCR 未配置，当前支持人工录入并注明原图位置及待确认。

补充记录格式示例见 `docs/saved-product-record.example.json`，只说明本地格式，不是实际商品数据或平台官方格式。导入后确认字段，并用“补存资料包”生成对应版本。不能使用截图默认值或新建表单占位值。

## Windows 启动

本机需已安装 Google Chrome。请按当前终端类型选择命令；CMD 跨盘进入项目必须使用 `cd /d`。

### CMD（提示符例如 `C:\Users\未>`）

```bat
cd /d D:\AI_Ecommerce
if not exist ".venv\Scripts\python.exe" python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

第一行执行后，确认提示符已经是 `D:\AI_Ecommerce>`。单独使用 `cd D:\AI_Ecommerce` 不会在 CMD 中切换当前盘符，可能导致误在用户目录创建虚拟环境、找不到 `requirements.txt` 或提示未安装 `uvicorn`。

### PowerShell（提示符以 `PS` 开头）

```powershell
cd D:\AI_Ecommerce
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/` 进入“商品采集”；顶部导航还可分别打开 `/progress` 的“采集进度”和 `/products` 的“已保存商品”。`/collection` 仍指向采集页。更新项目后请重启原服务进程。一次最多输入 50 个链接，每行一个，商品与店铺链接可以混合；支持淘宝/天猫商品链接、公开店铺首页或全部商品列表，也支持淘宝 `e.tb.cn` 分享短链接。

应用使用单个串行 Worker；同一数据目录只启动一个应用进程，勿使用多 Worker 或同时启动多个实例。任务历史在“采集进度”独立分页，可按来源或状态查找；“已保存商品”可按名称、商品 ID 和平台查找并分页。两个页面的“查看结果”使用相同弹层。进度页的批量暂停/继续/重试按钮只作用于当前页显示的任务；各任务也可独立操作。新建采集默认选择“重新读取最新资料”，也可显式选择“复用已有资料”；两种方式均保留独立批次及保存目录，并优先复用已校验原图。失败商品仅补未完成内容。旧接口不带目录时保留原任务复用行为。

店铺每发现一组链接便建立商品任务，暂停继续发现链接，先逐件执行“请求商品页面 → 解析基础信息、属性及 SKU → 下载原图 → 保存完整资料包”，再继续下一组链接。不会等几百件商品的信息全部取得后才开始下载。已有暂停任务的 `discovered_urls` 优先转成商品任务处理，原目录及断点保留。完成当前已发现商品不代表整个店铺链接已发现完毕；进度页明确说明这一点。

店铺任务优先显示页面识别出的真实店名，商品进度优先显示商品标题；旧任务可从已保存的店铺页面快照和商品资料补齐名称。名称尚未取得时暂以店铺域名或商品 ID 标示。店铺卡片显示当前第几件商品、获取页面/解析资料/浏览器等待及操作/原图下载等具体步骤，并随页面每 3 秒刷新显示最近更新时间。此时间表示最近进展，不是剩余时间预测；网络请求或页面加载可能持续到各自的超时上限。

任务卡片上的“删除任务”会将该任务从列表移除；“删除本页任务”只删除当前页显示的任务，点击后可确认或取消。未完成采集会停止，其它店铺或独立商品任务仍需要的共享工作会继续。已保存的商品资料、原图和数据库历史记录保留，仍可在“已保存商品”查看和导出。重启后删除的任务保持隐藏；重新添加相同链接时复用原成功结果或未完成部分的检查点。

## 服务器配置与访问方式

可将 `.env.example` 复制为 `.env` 后配置；操作系统环境变量优先。`.env` 已被版本管理忽略，密钥只由服务器读取，界面与任务结果不返回密钥。

```dotenv
SCRAPERAPI_KEY=
SCRAPERAPI_ENABLED=false
SCRAPERAPI_TIMEOUT=70
SCRAPERAPI_MAX_ATTEMPTS=2
```

配置有效密钥并启用后，每件需重新读取的商品各发起一次独立 ScraperAPI 渲染请求（`render=true`，该次商品处理只发送一个 HTTP 请求），随后立即解析、下载并保存，再处理下一件。商品请求不使用自动 HTTP 重试；超时、额度或 HTTP 错误明确失败，人工点击重试时才开始下一次处理。仅已请求商品自身需要验证或渲染结果不完整时，使用保留的 Playwright 会话补充；原店铺登录状态不再让全部商品跳过 API，旧任务中未采集子商品继承的登录标志也会修正。商品已有信息检查点时，暂停、重启及图片下载失败重试从原图/资料保存阶段恢复，不重复取得页面。显式复用已有资料不请求商品页面，并显示来源时间。

店铺列表发现与商品页面请求分别计数；列表的动态滚动、点击或登录仍可能使用浏览器。店铺请求及连接测试仍按 `SCRAPERAPI_MAX_ATTEMPTS` 做有限重试。原图通过原始图片地址下载，并沿用原图校验、去重及质量保留，不为每张图片再请求一次 ScraperAPI。进度卡片显示每件商品的实际请求次数、渲染方式、最终页面来源及浏览器补充原因；没有计数的历史商品标为历史未记录。连接测试使用独立客户端，不受上一任务的暂停检查影响，也不计入商品次数。

渲染请求比普通请求消耗更多额度，实际扣费以服务商账户为准，参考 [ScraperAPI 渲染说明](https://docs.scraperapi.com/resources/faq/js-rendering)。各商品可以使用同一密钥；独立请求不能保证淘宝永远不会要求验证。启用但没有密钥时商品明确失败，不伪装成 API 采集；显式停用 API 时仍保留原浏览器模式。密钥经请求头认证，不加入 URL、资料包或日志。此前的 `SCRAPERAPI_MODE` 已不再使用。

可用下面命令测试服务器端 ScraperAPI 配置；这是一次真实 API 请求，测试只输出配置状态、HTTP 状态、耗时和出口 IP：

```powershell
.\.venv\Scripts\python.exe -m scripts.check_scraperapi
```

采集页的“测试连接”按钮使用同一服务器配置发起真实 ScraperAPI 请求，并在页面显示测试中、成功或失败状态；它不会返回或显示密钥。失败时可能按服务器配置重试，测试请求可能计入 ScraperAPI 用量。未启用或未配置时按钮不可用并显示原因。

## 浏览器登录、等待与恢复

默认启动可见 Chrome，并保存会话到 `data/playwright/taobao_profile`。打开或重新访问商品/店铺页面、点击、滚动、翻页，以及为加载详情图片进行的点击、滚动和悬停等浏览器操作，每次独立随机等待 0.5–1.2 秒。每次等待期间每 0.2 秒检查暂停。原图通过 HTTP 直接下载，不增加随机等待；页面读取、元素查询和本地操作也不增加随机等待。页面自然渲染和异步加载仍需相应完成时间，已经滚到底部时只观察内容稳定性，不重复滚动。

遇到登录、验证码或风控时，任务暂停并显示原因。请在保留的浏览器窗口人工完成，再点击“人工完成后继续”。任务使用同一会话重新打开原地址，检查最终目标及验证状态；未解决时再次暂停，不会无限重试。不要删除浏览器 profile。也可通过 `AI_ECOMMERCE_CHROME_CDP_URL` 接入已开启调试连接的 Chrome；该设置只用于本机已有浏览器会话。

人工处理期间该任务占用采集浏览器，其它浏览器任务等待；能通过公开 HTML 完成的任务仍可执行。暂停该任务可释放占用。店铺仅需要动态翻页时，子商品仍逐个优先获取公开页面；实际发生登录验证后才继承浏览器会话需求。

暂停会在等待和下一步操作前生效；已经发送的页面/图片请求需返回或超时后才能停止。解析结果及逐图成功记录会保存为检查点：暂停、失败重试和进程重启后，仅下载未完成图片；没有有效图片的页面会在重试时重新获取。需要登录恢复的任务固定使用原浏览器会话，不再次请求匿名公开页面。

店铺成功发现的页面和下一页位置也会保存。公开分页与具有独立地址的浏览器分页从未完成页继续；地址不变的 JavaScript 翻页会保留待执行动作，暂停后沿用当前页面。浏览器进程已经退出时，纯客户端分页/加载状态需要通过必要的浏览器操作重建；已发现商品、采集快照及成功下载的原图仍复用。人工登录恢复会先重新访问原店铺确认有效，再回到未完成页。

## 数据目录与导出

默认数据目录为项目下 `data/`，可用 `AI_ECOMMERCE_DATA_DIR` 指定。沿用原数据库 `data/database/app.db`，现有商品、原图、任务和历史表不清理。启动补充读取旧版本数据所需的缺失列及准备资料相关新表，并将上次中断的采集和本地保存恢复；其它已退役业务的历史任务保留但不执行。

- 原始图片：`data/products/{product_id}/original/`，UUID 文件名，已存在文件永不覆盖。
- 内部旧资料缓存：`data/products/{product_id}/source/product.json` 和 `product.csv` 保留兼容；新的完整资料包自动写入每批选择的目录。旧任务未指定目录时默认写入 `data/prepared/`。
- 浏览器会话与页面证据：`data/playwright/`。
- 下载：界面中的原图下载、单商品/店铺 ZIP、本页结果 ZIP；ZIP 内图片字节与本地原图一致，多商品以商品 ID 子目录区分。

文件大小及 SHA-256 校验决定原图是否完整。丢失或损坏的图片会保存为新文件补齐，原有文件与记录保留。旧商品导出会从保留的商品记录和原图生成新版完整资料包，来源不明确的实际设置仍标为未获取。原素材编辑、AI、审核、发布及回收站页面、接口和服务已移除；历史数据库表仍保留。
