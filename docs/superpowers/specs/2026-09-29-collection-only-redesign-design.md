# 采集下载工具收敛设计

## 目标

将 AI_Ecommerce 收敛为只负责批量采集商品资料、下载原始图片、查看任务结果并导出文件的本地工具。现有商品资料、原始文件、数据库记录和任务历史必须继续可读；已经成功的商品和图片不可重复覆盖。

## 用户流程与界面

应用只提供采集下载工作流：输入多个商品 URL 或店铺 URL，开始采集，查看批次及商品级进度和结果，暂停或继续，重试失败商品，并下载原始图片和导出商品资料。页面不再显示素材编辑、AI、审核、发布、回收站等其它业务入口。删除对应的页面路由、API 和专属业务模块；保留采集结果及下载所需的商品与资产读取能力。启动首页直接进入采集工作台。

## 采集访问策略

统一由商品/店铺采集器协调 ScraperAPI 与 Playwright。ScraperAPI 仅从服务器配置读取密钥并获取符合公开页面策略的内容。成功取得且内容足以解析的页面直接进入现有淘宝解析器，不再访问浏览器。访问限制、动态页面或交互式店铺列表等需要浏览器能力时，使用持久化 Playwright 会话完成渲染、滚动、翻页和人工登录。只有明确的页面访问失败可触发另一种访问方式；登录、验证码、解析错误、本地存储错误不得触发重复网络请求。两种访问方式的结果汇入同一解析、商品保存和原图下载流程。

ScraperAPI 密钥留在服务器配置，不出现在页面、响应、持久化任务结果或日志。移除不再提供的网络模式切换界面/API（如果不再需要），保留必要的服务器端配置与安全连接测试能力仅在其仍服务采集流程时。

## 浏览器操作节奏

Playwright 的自动化页面操作统一经过一个可中断检查的同步节奏封装。每次 `goto`、点击、滚动、翻页、刷新或重新访问之前独立随机等待 0.5–1.2 秒，并在等待期间检查任务暂停/取消状态；发生暂停时不得执行待执行的浏览器操作。登录页面中的人工手动交互不由自动化节奏器包裹。页面读取、元素定位、解析和本地文件操作不加等待。等待时长每次单独随机产生，不能按批次复用。

## 登录恢复与暂停

需要登录或验证码时，将任务转入可见的人工处理状态并展示具体原因。用户完成登录后点击继续，任务用原有持久化浏览器会话按原商品/店铺 URL 重新访问；访问后检查最终 URL、登录/验证标志及目标内容，确认页面有效才开始解析。若仍在登录或验证页、目标失效或再次出现明确验证，则任务再次暂停并更新原因；不会自动无限循环。应用重启及显式继续均沿用保存的浏览器上下文。

## 数据保留、幂等与原图

继续使用现有 SQLite、商品、任务和采集任务记录以及既有数据目录。启动时兼容已有数据库，不删除或重建数据库表。采集按商品 ID 去重，已成功的商品任务不重建；每张图片按来源 URL、已保存有效原图和内容哈希识别可复用记录，只为缺失或不完整的部分续跑。下载内容作为 Original 原样保存，不进行缩放、裁切、压缩或其它变换，也不覆盖已存在文件。暂停、进程重启和失败重试从持久化任务状态继续。店铺父任务可统计子商品任务状态，并只重试未完成商品。

## 文件与配置清理

删除只被非采集功能使用的 AI Provider、素材编辑/视频处理、审核、发布、回收站等路由、服务、模板、脚本和专属静态文件。保留 SQLite 数据库中的历史表、行与关系，以免既有数据库或历史商品/任务无法读取；清理运行依赖时只移除删除业务后不再被采集、存储或测试引用的包。更新 README 为采集工具启动、数据目录、服务器端 ScraperAPI 配置、持久化浏览器登录、采集恢复和导出说明。验收/历史文档中删除或归档与已移除功能有关的过时运行指令。

## 验证要求

增加或调整有针对性的测试覆盖：每次浏览器自动操作产生新的 0.5–1.2 秒等待且暂停可打断；页面采集访问器只在允许的访问错误下切换而不重复已成功请求；成功的公开 ScraperAPI 页面不启动浏览器；登录后继续复访原目标并验证页面；仍需登录/验证时进入人工处理且无循环；重试仅下载缺少图片并保留既有原图字节；多商品链接输入、店铺父子任务恢复、资料导出和旧数据库可读取。运行采集相关 pytest 和前端脚本语法/轮询检查；不把离线样例通过等同于真实淘宝、ScraperAPI 凭据或登录环境验收。

## 设计边界

不删除用户数据，不迁移或改写已有原图。不实现商品编辑、素材加工、AI、审核、发布等非采集业务。真实站点兼容性、访问权限、验证码行为和有效 ScraperAPI 凭据需在部署环境现场确认。
