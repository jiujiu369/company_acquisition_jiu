# 逐件请求、采集和下载改进

## 实际行为

每件需重新读取的商品独立发起一次 ScraperAPI 渲染请求，随后解析基础信息、属性、SKU 和素材关系，下载原图并尝试保存完整资料包，再处理下一件。图片仍从原始图片地址下载，保留原图质量、校验、去重和断点；不是每张图片额外调用一次 API。

店铺列表只承担发现链接；每发现一组即交给商品任务串行完成，不等待所有店铺页发现结束。旧暂停任务中的已发现链接先处理，随后恢复原分页位置。店铺验证不再强制所有商品使用浏览器；旧任务中尚未读取商品继承的登录标志亦作窄范围修正，商品自身的验证和下载来源检查点保留。

一次商品页面处理只发送一个 HTTP 请求，不自动重复付费请求。HTTP/额度/超时错误明确失败，用户重试时再开始新的一次处理。已取得的信息、图片下载重试和暂停重启使用原检查点；选“复用已有资料”不重新请求页面。新建采集默认选择“重新读取最新资料”。已有批次的读取方式保持原选择。

API 页面要求登录或渲染结果不完整时，保留浏览器补充机制，提示原因，人工完成后继续。多次独立请求使用同一配置密钥；不保证平台永不要求验证。停用 API 的原浏览器模式保留；当前实际配置已确认 API 启用且有密钥。

## 修改位置

- `app/collection_service.py`：增量生成商品任务、优先处理已发现链接、原子写入链接和分页断点、请求计数、旧继承状态修正、发现未结束的准确状态。
- `app/scraperapi_service.py`：商品渲染与单次 HTTP 尝试、请求回调、浏览器补充原因、分页恢复、独立连接测试。
- `static/js/collection.js`：每商品实际请求次数、页面来源及补充原因；分别显示商品请求和店铺列表请求。
- `templates/collection.html`：默认重新读取及逐件处理提示。
- `README.md`：更新访问策略、恢复规则、计数和额度说明。
- 新增 `tests/test_per_product_strategy.py`，按新处理顺序更新原分页恢复及界面测试。

## 使用与范围

刷新采集页面，选择保存文件夹后新建采集。此前的 271 链接批次仍记录原目录 `D:\施科商品信息采集\批次_20261005055955_336655`，但已在本次修改前被用户删除隐藏（`removed_at=2026-10-05T06:15:47.519376Z`，内部任务状态 CANCELED）。现场检查发现这一点后，保留删除及暂停状态，没有自动恢复；新建采集使用新策略。未删除的暂停任务继续时仍继承其原目录与已发现链接。

商品字段模型、人工修改、版本历史及四项物流排除规则不变。ScraperAPI 获取公开页面；卖家真实库存、编码、后台属性和实际渲染响应完整性仍需真实页面确认，未知值不会因此补成默认值。商品采集状态、范围内必填完整度和资料包保存状态仍分开显示，保存失败可补存。

渲染请求消耗更多额度，实际费用看账户；参考 [ScraperAPI 渲染说明](https://docs.scraperapi.com/resources/faq/js-rendering)。店铺列表及连接测试的请求另计，不能用商品数量推断账户总用量。
