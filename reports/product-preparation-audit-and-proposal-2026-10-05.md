# 商品资料准备：现状检查与建议设计

日期：2026-10-05（Asia/Taipei）

状态：检查完成；建议设计待用户审阅，尚未修改业务代码、数据库结构或采集流程。本文件不是已实现功能说明。

## 1. 目标及边界

把用户自己的淘宝/天猫现有商品整理为人工可检查、程序可准确读取、能够移动并离线查看的商品资料包。沿用现有采集、数据库、缓存、登录会话、原图及恢复机制，不实施商品上架、下架或修改。

五张截图仅用于确认填写项与星号；其中新建发布页的默认库存、上架方式、发货时效、运费模板及帮助文案不是原商品资料。截图中的“重要”标签不作为必填依据。

发货时间及发货时效、发货地、提取方式、运费模板及其名称/ID/规则/包邮条件，全部排除于主动采集、商品字段导出和必填检查。原有不可修改的历史证据不清理；新资料包中的字段通过明确白名单生成，不能直接倾倒整个网络响应。

“3:4 主图”“店铺中分类”按具体字段范围中的“不选”处理，不主动纳入本次资料字段。虽然数据来源章节提及后台店铺分类，本设计以更具体的“不选”为准。当前类目与店铺分类是不同字段。

### 已复现的准确性问题

使用自行构造的隔离页面样例，不使用截图作为商品数据：

1. SKU `quantity=0` 且不存在 `stock` 时，通用解析的 `quantity or stock` 返回 None；明确的零库存丢失。
2. 价格字符串 `10-20` 被解析为 `10.00`；区间和实际一口价没有分开。
3. 主图与详情使用相同 URL 时，按 URL 合并只留下 `detail` 用途。
4. ParsedProduct 没有详情文字/图文块字段。
5. 资料 JSON 写入服务器绝对素材路径，但 ZIP 把素材放入另一套 `images/` 路径；移动资料不能保证引用有效。
6. 成功商品按来源 URL/商品 ID 全局复用旧任务；没有新的批次保存请求，不能保证另一个目录产生资料包。
7. 重新采集用同名键覆盖 current_data；没有可靠机制判断旧 current_data 哪些值是人工修改。

## 3. 实际读取能力核实

源码能确认：当前只接受公开商品/店铺地址，遇到卖家/登录保护页面会要求人工处理；没有官方接口授权流程、卖家导出解析器或已保存商品后台读取适配器。

当前浏览器只读检查发现 Chrome 连接，但页面枚举返回 `nodeRepl.fetch request failed`。因此不能判断用户是否已登录卖家后台，也未取得原商品后台字段、导出入口或权限证据。不能把这次错误描述为“用户未登录”或“后台没有相关字段”。

后续读取路径必须先核实，再启用：

1. 从用户可访问的原商品列表/已保存商品记录进入只读数据页，确认商品 ID 与目标一致。
2. 只读取页面已保存的数据或该页面实际返回的数据；不得读取新建发布表单默认值，不得猜测隐藏接口或尝试写接口。
3. 官方导出只有在确认当前账号具有入口、导出文件内容和字段后，才增加该文件格式适配器。未核实前不宣称可以获取所有字段。
4. 后台读取走已登录本地浏览器，不通过公开页面代理发送登录凭据或卖家资料。
5. 登录/验证交给用户完成。仅允许经过验证的导航、查看和翻页；不得触发保存、提交、上架、下架、删除等动作。
6. 商品 ID 关联商品，来源 SKU ID 关联 SKU；没有 SKU ID 时只能使用已验证的完整规格 ID 组合，不能按标题或相似文字匹配，歧义必须待确认。

无法取得的值保留未知状态与具体原因；不以买家库存提示或优惠价代替卖家实际值。

| 方案 | 结果与代价 |

## 5. 推荐设计：稳定商品结构

新增版本化准备结构，沿用 `local_product_id` 作为稳定本地身份。来源商品和 SKU ID 明确为追溯 ID，不生成未来平台 ID。

顶层建议固定为 `schema_version`、`local_product_id`、`source_product_id`、`source_platform`、`sources`、`captured_at`、`capture_id`、`collected`、`manual_overrides`、`effective`、`media`、`detail_blocks`、`completeness`、`issues`、`listing_history`。JSON 使用 UTF-8；CSV 使用 UTF-8 BOM 和稳定英文列名，嵌套结构以明确的 JSON 单元格保留。

### 字段值与状态

每个值保存 `value`、`status`、`source_refs`、`observed_at`、`reason`、`needs_confirmation`。四种未知状态必须分别保存：

- `not_set`：原商品明确未设置，有对应证据。
- `not_applicable`：确认该商品/类目不适用，有依据。
- `not_obtained`：尚未读取、来源未开放或无法从现有来源取得。
- `failed`：已尝试读取但失败，记录具体错误。

已取得用 `obtained`。OCR 未确认、来源冲突、类目规则未核实使用独立的 `needs_confirmation`，不能用空字符串或 0 掩盖。字段支持“已取得”不等于保证真实页面一定能取得。

来源包括商品 ID、链接、读取方法、时间、证据定位；冲突保留各来源原值和处理状态。默认优先使用已验证的卖家实际设置，但不删除公开展示值；人工明确修正优先形成最终值。

### 分组与数值

- 标题与导购标题独立。
- 类目保存 `name`、`path`、`source_category_id`；只有确证才给出完整路径和 ID。
- 属性采用列表，保留原名称、原始值、来源属性 ID（如有）、独立单位；可靠依据存在时增加 normalized_value，不强行映射平台选项。
- 金额保存十进制文本、currency 及来源；促销价、券后价和区间进入 `buyer_display`，不能冒充 seller_price。
- 库存数量与单位独立；0 是已知零，未知是 null。只取得部分 SKU 库存时不生成完整总库存。只有有证据证明 SKU 集合完整且每项为实际库存时，才可生成有来源说明的派生总库存。
- 上架方式、相关时间及当前销售状态保存于 `listing_history`；后续新上架时间/操作设置保持待用户决定，不能复制历史时间作为未来设置。

### SKU 与素材关系

每项 SKU 保存稳定本地 SKU 标识、来源 SKU ID、原顺序、完整规格维度/值/组合、实际价格/库存、商家编码、条形码、可售状态、图片资产 ID 及状态。手工 SKU 修改以本地标识和来源标识绑定，不以数组序号绑定。

素材文件与用途分离：一个原文件可以拥有多条角色引用。引用保存用途、用途内顺序、首图标记、相对路径、对应 SKU、来源 URL、哈希、字节数及读取时间。保留重复出现在详情中的位置，不因下载去重改变图文顺序。

主图明确标记 1:1 用途；尺寸不符合或无法证明用途时列待确认，不自动裁剪。详情、SKU、白底图、家装家居卖点头图、商品视频、购后视频分别标记；额外素材仅在有原商品配置证据且能取得时保存。

详情按 DOM 顺序形成文字/图片块；离线 HTML 安全转义、只引用本地文件，不加载远程脚本、表单或 iframe。读取失败图保留位置及错误，不悄悄把主图充作详情。图片中的参数可采用经核实的本地 OCR 能力作为辅助证据，保留原图、识别文字、区域及待确认状态；没有可用 OCR 时说明未识别。不得从外观推断材质、品牌、认证。

## 6. 必填清单与字段覆盖

所有商品通用必填：标题、当前类目、1:1 主图、宝贝详情、一口价、总库存、原商品上架设置。上架设置无法读取时保留缺失/原因；这是来源记录，不是未来操作指令。

截图接线端子类目的属性必填：安装方式、导体材质。只有确证类目适用时才启用该规则。其他类目使用经核实的规则；规则未核实显示“类目必填要求待核实”，不能宣布必填资料齐全。

可选字段结构覆盖：导购标题、型号、SV 型号、外壳材质、产地、触点镀层、电源配件、定制服务、额定电流/电压及单位、防护等级、国际认证、极数、密封件材质、耐温等级及单位、品牌、行业认证、振动等级、阻燃等级、最小起订量及单位、宝贝类型、采购地、自定义属性、销售规格、购买须知、商家编码、多件优惠、商品预检、库存扣减方式、自定义宝贝规格、商品条形码、区域限售、可编辑的售后服务，以及实际取得的额外素材。

“商品属性”是分组；不生成名为商品属性的独立值。禁用且无需填写的服务控件、推荐说明与平台帮助不入字段。

必填判定同时检查值、状态、确认事项、素材可用性和类目规则。任何必填缺失、错误地标为未设置、待确认或规则未知都不能显示齐全。不适用的必填例外必须有证据，不能任意跳过。

四项物流信息、3:4 主图、店铺中分类不进入上述清单。界面固定用“采集范围内必填资料齐全”，不使用“已满足全部上架条件”。

## 7. 每批保存、版本与补存

采集前增加“保存到”：完整路径输入、Windows 实际文件夹选择、记住上次选择；支持更换。浏览器文件上传控件不能代表服务器真实保存目录，不能用 ZIP 下载代替自动保存。

新批次记录包含选定根目录、实际批次目录、采集模式及创建时间。建议在选定目录下创建 `批次_时间_短ID/商品ID_简短标题/`。数据库永久保存批次目录，所有子商品继承；暂停、重试、重启都不重新读取全局偏好。旧任务缺少目录时继续使用旧内部路径并显示旧任务状态，不回写猜测的目标。

创建任务前实际检查目录存在、类型及读写，并创建/删除独立探测文件；这不能保证后续永远可写，所以复制时仍处理权限、磁盘满、断开及中断。路径清理覆盖 Windows 非法字符、保留设备名、尾部空格/点、中文、空格、重名、标题截断与总路径长度；必要时保留商品 ID 并缩短标题。目录取消选择不创建任务。

每件商品的完整版本目录至少包含：

```text
商品ID_简短标题/
  版本_时间_捕获ID_人工修订ID/
    product.json
    product.csv
    skus.csv
    README.html
    detail.html
    media_manifest.json
    sources.json
    issues.json
    assets/原图资产ID.原扩展名
```

实际保存路径指向完整版本目录；所有内部引用使用此目录内相对路径。每次更新生成独立完整版本，不用覆盖旧备份换取“最新”。可增加只含最新版本位置的轻量索引，但历史版本资料不能变。

JSON 同时保留采集、人工及最终值；人读文档和 SKU CSV 展示最终值并标注修改与来源；JSON 是后续程序读取的权威结构。通用 CSV 明确标为整理格式，不宣称平台可直接导入。

复用已有资料与重新读取最新资料由用户在采集前选择，显示原资料时间。商品缓存复用与批次保存请求分离：即使没有再次访问页面，新目录也创建并校验一份完整资料包。刷新来源生成新 Capture，但保留人工层。

保存记录独立于采集任务状态，建议包含 `batch_id`、`task_id`、`capture_id`、`manual_revision_id`、`target_path`、`status`、`error`、`verified_at`。内部商品先持久化，外部资料保存失败不能回滚已取得的商品。包内文件先写临时目录、校验清单及哈希，最后提交完整标记；未完成包不显示保存成功。

支持重新选择目录后补存、只重试保存、重启后继续保存；补存不重新访问淘宝，也不重下已校验原图。改目录记录新保存目标及历史失败原因，不把旧失败静默擦掉。复制原图采用字节复制，不缩放、不重编码；历史原图不覆盖。

## 8. 人工补充及旧数据兼容

增加独立人工修订记录，保存字段路径、状态、值、修改时间、依据及修订版本。重采只更新采集层，effective 通过人工层覆盖后生成。清除人工覆盖需要显式操作，并保留修订历史。

旧 raw_data、Capture、current_data、SKU 和素材记录保持原样。旧 current_data 是否包含人工修改无法从现有结构可靠判断；兼容迁移应保留一份完整原值快照，并将不能证明是采集值的差异列为“历史值待确认”，不能直接视作采集值覆盖。没有来源证明的旧价格/库存不能升级成卖家实际值。

增加新表或兼容字段，不删除历史表。旧资料需生成新版包时读取旧记录及原图，缺失项显式标记；新增字段不填截图默认值。素材按本次 Capture 的用途引用生成包，不把数据库全部历史素材误认为当前主图。

## 9. 界面改进

- 采集页：保存路径、选目录、目录检查结果、复用/重新读取选项。
- 进度页：分别展示“采集任务”“采集范围内必填资料”“资料包保存”；批次与子任务能查看各自目录和错误；保存失败提供重新选目录和补存。
- 已保存商品/统一弹层：资料时间、版本、来源、缺失/待确认/冲突、用途与顺序、首图、完整 SKU 图片关系、可编辑字段及人工修订标记。
- 原商品上架记录明确标为历史来源；本次不生成新上架操作配置。
- 保留既有暂停、继续、登录处理、重试、搜索与分页。

## 10. 实施顺序及验证清单

实施按数据结构和缺陷修复、资料包与保存记录、批次任务衔接、人工补充、界面展示、真实卖家来源核实顺序推进。需要调整的旧复用测试应明确新契约：缓存可共享，批次保存请求和目标不能共享覆盖。

验收至少覆盖：

| 场景 | 通过条件 |
| --- | --- |
| 单商品与多 SKU | 规格组合、SKU ID、价格、库存、图片与顺序准确，缺图保留错误位置 |
| 卖家来源可读/不可读 | 以商品 ID/来源 SKU ID 关联，记录能力和原因，未知不补默认值 |
| 买家价格区间/促销/库存 | 保留为展示信息，0 库存不丢失，部分库存不冒充总库存 |
| 必填缺失/不适用/识别不确定 | 四种状态分开，未核实类目规则不能显示齐全 |
| 物流排除 | 从采集结构、JSON/CSV、人读资料与完整度检查验证四项物流字段均不出现 |
| 详情图文/重复图片用途 | 图文顺序和重复引用不变；同一文件允许多个角色 |
